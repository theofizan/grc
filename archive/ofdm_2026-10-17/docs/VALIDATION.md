# Software validation and evidence

The primary [SISO report](../results/REPORT.md) summarizes 34 complete finite executions of the two new Qt live labs. The [appendix](../results/VALIDATION_APPENDIX.md) retains earlier reference calculations and the command index. Seven .grc graphs compile; five software graphs execute, and two one-channel UHD graphs are compile-only.

New checks include native bit mapping/decisions/counters, fixed active PPDU power across rates, fixed-noise loss sweeps, complete sample/bit/burst counts, noiseless recovery, causal multipath, CFO recovery, and a corrections-disabled GRC replay of identical stored IQ. Each actual Qt graph runs with native sinks and an event loop using the offscreen platform. MATLAB independently validates all 34 shared symbol fixtures; its receiver independently checks 20 flat AWGN/no-tracking captures. Complex64 live receiver symbols have a separate 2e-6 absolute comparison tolerance; the older offline complex128 receiver comparison retains its tighter tolerance.

GUI runtime tests uncovered a Qt5/Qt6 Qwt mismatch invisible to compilation. Radioconda now pins Qwt 6.3.0 build h4ff56cd_0 (Qt5). The installation diagnostic constructs an actual native Qt plot in a subprocess. See the SISO report for the transaction evidence and current checks.

Run `python scripts/run_all.py` in the radioconda environment. The current complete software run is recorded in `results/validation/status.json`; each step's stdout/stderr is archived alongside it. That manifest, rather than prose copied into a paper, is the source of truth for the actual command status, timestamps, versions, and source hashes.

## Numerical and statistical interpretation

- Exact theory agrees with `berawgn` to approximately 1e-14 relative error where the oracle BER exceeds 1e-14 in the executed 0-20 dB range. The assertion allows 1e-5 relative error to accommodate platform/library differences; actual errors are saved.
- Shared symbols must produce identical bit counts and error counts. EVM uses complex128/double arithmetic; the cross-language assertion allows 5e-7 absolute difference, while actual differences are much smaller.
- Wi-Fi cross-validation asserts maximum complex symbol difference below 1e-9 and pooled EVM difference below 1e-10. Executed results are around 1e-15 and 1e-17 respectively. These compare algorithms operating on the same stored single-precision IQ, not independent noisy experiments.
- GRC's native FFT operates in complex64, whereas the NumPy reference uses complex128. The validator uses `atol=2e-6, rtol=2e-5` and saves both maximum absolute and relative L2 errors. The sample-count/vector-shape comparison must also pass; this catches misaligned CP removal and dropped samples.
- Independently seeded Monte Carlo curves should statistically agree with theory, not agree sample-for-sample. Finite-count zero-error points are upper limits. QAM/FEC error correlation makes independent-bit confidence intervals nominal; see THEORY.md.
- The reference packet exporter uses a common TX scale across all rates. The reference data are metadata, not estimates fitted to the RX payload. Python's known TX FFT normalization is checked for constancy before use.

The defaults use 100000 symbols per uncoded simulation point, 16 repeated PPDUs per rate for GRC replay, and 12 independently noised packets per coded-curve point. These software demonstrations are intentionally smaller than the proposed RF study's 1000 transmitted packets per measurement point and three repetitions. Their different sizes are explicit and are not silently interchangeable.

## Untested or intentionally limited

1. **Hardware:** the UHD TX/RX graphs are compiled only. No USRP connection, RF transmission, cabled baseline, antenna comparison, power calibration, or stream-integrity commissioning was performed.
2. **Steering:** only the mock backend runs. A real serial/network/SDK adapter, readiness policy, and frequency-dependent calibration remain hardware-specific work.
3. **Acquisition:** the tested WLAN scorer knows the packet schedule/rate/length. Autonomous packet detection, L-SIG-driven configuration, independent-clock CFO/sample-timing tracking, and measured acquisition loss are not validated.
4. **Channel:** the older offline cross-checks use AWGN. The new SISO labs additionally test causal multipath and STF/LTF CFO/pilot correction with known burst timing. Sample-clock mismatch, arbitrary unknown delay and general multipath acquisition remain untested. The older MATLAB helper's optional CFO path is separate from the new receiver and is not claimed validated by its AWGN checks.
5. **Conformance:** a WLAN Toolbox PPDU and successful software decoding do not establish a certified transmitter, complete MAC interoperability, or antenna-only EVM compliance.
6. **Statistics:** the coded curves' packet count is exploratory. Repeated synthetic payloads and nominal bit-binomial intervals do not substitute for a full RF uncertainty analysis.

## Reproducibility artifacts

Keep the run status, source hashes, CSV/JSON/MAT files, figure source scripts, raw reference/capture files, exact configuration, and bibliography together. The full runner overwrites its results by design. Archive each experimental run under a unique identifier before changing settings or collecting another antenna/angle point.
